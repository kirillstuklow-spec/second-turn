# Arena Runtime 0.6.5.1

Первый этап вертикального среза арен:

`ArenaData → BattleState → CellRuntime → BattlefieldView → настоящий бой`.

На этом этапе отдельного CellBuilder и ArenaBuilder ещё нет. Сначала проверяется,
что Runtime действительно умеет использовать те данные, которые позднее будут
создавать редакторы.

## Установка

Пакет устанавливается поверх уже проверенной версии с UnitBuilder 0.6.

1. Закрой Godot.
2. Распакуй архив в корень проекта рядом с `project.godot`.
3. Разреши объединить папки и заменить существующие файлы.
4. Открой проект в Godot 4.6.3.
5. Дождись завершения импорта новых скриптов и ресурсов.

## Что должно появиться

В `battle_scene.tscn` узлу `BattleEngine` уже назначена:

`Resources/Arenas/Arenas/TestArena.tres`.

После запуска боя должно быть видно:

- поле 7×5 из тестовой текстуры `icon.svg`;
- серо-синие клетки по умолчанию;
- вертикальная акцентная полоса другого цвета в колонке `x = 3`;
- четыре прежних юнита поверх клеток;
- работающие движение, способности, ходы, смерть и победа.

Тестовые изображения намеренно используют существующий `icon.svg`. На следующем
этапе CellBuilder позволит создавать такие визуальные клетки из импортированных
PNG без ручной работы с `.tres`.

## Проверка независимости слоёв

У арены визуалы и зоны хранятся отдельно.

В `TestArena.tres`:

- визуальная акцентная полоса занимает всю колонку `x = 3`;
- зона размещения первой стороны задана только в `(0,2)` и `(0,3)`;
- зона размещения второй стороны задана только в `(6,2)` и `(6,3)`;
- остальные клетки относятся к нейтральной зоне.

Визуальная клетка поэтому не содержит и не определяет игровую зону.

## Проверка fallback

1. Открой `Scense/Battle/battle_scene.tscn`.
2. Выбери `BattleEngine`.
3. Очисти поле `arena_data`.
4. Запусти бой.

Должно появиться прежнее цветное поле с координатами и старой схемой зон.
Это подтверждает обратную совместимость с боями, у которых пока нет `ArenaData`.

После проверки верни:

`Resources/Arenas/Arenas/TestArena.tres`.

## Новые данные

### `CellVisualData`

Хранит только визуал:

- технический ID;
- название и описание;
- базовую текстуру;
- необязательную декоративную текстуру;
- оттенок;
- поворот кратно 90 градусам;
- отражение по горизонтали и вертикали.

Геймплейных свойств у визуальной клетки нет.

### `BiomeVisualData`

Хранит:

- ID, название и описание биома;
- визуал клетки по умолчанию;
- пул доступных `CellVisualData`.

Автоматическая генерация по биому пока не выполняется.

### `ArenaData`

Хранит:

- ID, название и описание;
- ширину и высоту;
- ссылку на биом;
- визуал клетки по умолчанию;
- отдельный список размещения визуальных клеток;
- отдельный список размещения логических зон;
- цвет фона.

Размер хранится в данных для будущего расширения, но текущая версия валидирует
только поле 7×5.

## Изменённые Runtime-компоненты

- `BattleEngine` принимает необязательную `ArenaData`;
- `BattleState` строит клетки по арене и хранит фактический размер поля;
- `CellRuntime` получает ссылку на неизменяемый `CellVisualData`;
- `BattlefieldView` показывает текстуры, декорации, повороты и отражения;
- подсветка целей рисуется отдельным слоем поверх текстуры;
- `ArenaValidator` блокирует некорректные координаты и дубликаты.

## Что сознательно не входит в 0.6.5.1

- CellBuilder;
- ArenaBuilder;
- автоматическое заполнение биомом;
- игровые объекты и препятствия арены;
- ручная расстановка юнитов;
- изменение боевых правил.

Следующий этап после успешной проверки — CellBuilder, который создаёт и
редактирует `CellVisualData`. После него ArenaBuilder будет рисовать этими
ресурсами визуальный слой и отдельно рисовать зоны.

## Если возникает ошибка

Пришли:

1. полный текст первой ошибки из Godot;
2. список файлов, на которые она ссылается;
3. скриншот поля, если бой запускается, но отображение неверно;
4. содержимое Output от строки `BattleState: battlefield generated`.
