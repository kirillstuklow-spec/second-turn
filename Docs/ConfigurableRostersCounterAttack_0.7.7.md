# 0.7.7 — настраиваемые составы, автоспавн и «Контр-удар»

## Настраиваемые составы

`BattleEngine` предоставляет в Inspector два массива:

- `Player 1 Units`;
- `Player 2 Units`.

Размер массива является числом стартовых юнитов. Допустимо назначить один
`UnitData` несколько раз: каждая запись создаёт отдельный `UnitRuntime`.

Ограничения проверяются до создания первого юнита:

- от 1 до 6 юнитов в каждой команде;
- не более 12 юнитов суммарно;
- ни одной пустой ссылки;
- состав не превышает вместимость зоны расстановки своей команды;
- при ошибке частичный бой не запускается.

## Линейный автоспавн

`BattleInitializer` берёт только свободные клетки соответствующей зоны
`PLAYER_1_DEPLOYMENT` или `PLAYER_2_DEPLOYMENT`. Для обеих команд действует
один порядок: строки сверху вниз, внутри строки слева направо. Первый ресурс
массива занимает первую клетку, второй — следующую и так далее.

Тестовая арена содержит по шесть клеток расстановки:

```text
Игрок 1: (0,1), (1,1), (0,2), (1,2), (0,3), (1,3)
Игрок 2: (5,1), (6,1), (5,2), (6,2), (5,3), (6,3)
```

Эта конфигурация служит технической проверке и не является балансным
решением. Будущее меню расстановки сможет передавать те же массивы состава,
заменив автоматический выбор клеток выбором игрока.

## Карточка способности: «Контр-удар»

| Свойство | Значение |
|---|---|
| Владелец тестового ресурса | Белый брат |
| Категория | Пассивная автоматическая способность |
| `activation_mode` | `TRIGGERED` |
| Триггер | Владелец фактически потерял не менее 1 HP от `DamageImpact` |
| Фильтр взаимодействия причины | Только `MELEE` |
| Отношение к источнику причины | Враг владельца |
| Источник Контр-удара | Владелец способности |
| Цель Контр-удара | Источник события урона |
| Последствие | Один `DamageImpact` |
| Тип взаимодействия | `MELEE` |
| Источник | `PHYSICAL` |
| Величина | `ceil(фактически потерянные HP / 2)` |
| Бронебойность | `0` |
| Стоимость AP | `0` |
| Кулдаун / заряды / лимит | Нет |
| Выбор игрока | Нет; цель зафиксирована событием |
| Если владелец погиб от причины | Контр-удар не ставится в очередь |
| Реакция на другой Контр-удар | Нет; триггер не принимает события глубины реакции выше 0 |

Примеры величины:

```text
Потеряно 1 HP → Контр-удар на 1
Потеряно 2 HP → Контр-удар на 1
Потеряно 3 HP → Контр-удар на 2
Потеряно 5 HP → Контр-удар на 3
```

## Почему это способность, а не эффект

`ReactionSystem` находит `UnitAbilityRuntime` в списке пассивных способностей,
проверяет его `AbilityTriggerData` и ставит автоматическое применение в общую
`ReactionQueue`. Ответ строится из собственного `ImpactPlanData` способности.

Поэтому Контр-удар проходит обычный путь разрешения атаки:

1. иммунитет к `MELEE`;
2. иммунитет к `PHYSICAL`;
3. расходуемая защита от `MELEE`;
4. расходуемая защита от `PHYSICAL`;
5. броня с бронебойностью 0;
6. потеря HP и публикация обычного события урона.

Автоматический запуск убирает выбор цели и стоимость AP, но не меняет правил
урона. Контр-удар способен запускать другие подходящие эффекты и реакции,
кроме нового Контр-удара.

Урон уже находящегося на носителе эффекта остаётся другим случаем:
`EFFECT + источник` заново проверяет иммунитеты и защиты, но не проверяет
броню. Именно поэтому Горение и Разложение находятся «за бронёй», тогда как
внешний Контр-удар — нет.

## Контрольный тест

```text
Scripts/Tests/ConfigurableRostersCounterAttackSmokeTest.gd
```

Тест проверяет валидатор составов, повтор одного `UnitData`, порядок 6+6
клеток, динамическую величину от фактически потерянного HP, обычные защиты и
броню Контр-удара, запрет контр-цепи и отсутствие посмертного ответа.
