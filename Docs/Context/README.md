# Контекст проекта: точка входа

Эта папка — короткий актуальный вход в проект для нового диалога или нового
этапа разработки. Она не заменяет код, тесты и карточки реализованных механик.

## Что читать

1. `CurrentState.md` — какая версия принята, а какая только проверяется.
2. `PatchWorkflow.md` — как готовить следующий патч.
3. `ProvisionalBalanceDefaults.txt` — только при добавлении юнита, способности
   или другого контента с недостающими балансными числами.
4. Только карточку затрагиваемой механики из `Docs/`.
5. Затрагиваемые код, ресурсы и тесты.

Не нужно по умолчанию читать все документы проекта. Старый дизайн-документ
является историческим источником: обращаться к нему следует только по прямому
запросу пользователя или когда конкретного решения нет в актуальных источниках.

## Приоритет источников

При расхождении действует следующий порядок:

1. текущая явная инструкция пользователя;
2. код, ресурсы и тесты актуального репозитория;
3. `CurrentState.md` и актуальные архитектурные контракты;
4. карточки уже реализованных версий в `Docs/`;
5. старые таблицы, дизайн-документы, промпты и пересказы.

Конфликт между первыми четырьмя уровнями нельзя разрешать догадкой. Нужно
остановить изменение, проверить актуальность ветки и при необходимости спросить
пользователя.

## Проверка свежести

- Если пользователь сообщил о новом push, сначала сверить актуальную ветку.
- Если доступна только локальная копия неизвестной свежести, запросить ссылку,
  архив или подтверждение базовой версии.
- Не объявлять кандидат принятой версией до результата пользовательской
  проверки.
- После приёмки обновлять `CurrentState.md`; рядовая реализация способности сама
  по себе не требует переписывать все контекстные документы.
