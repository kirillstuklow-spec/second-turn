# Prototype 01 — Ability Pipeline Test

Версия: 0.1

Цель документа:
Зафиксировать минимальный играбельный прототип, который проверяет первый боевой Pipeline без поля, движения, инициативы и полноценной боевой системы.


==================================================
1. ЦЕЛЬ ПРОТОТИПА
==================================================

Prototype 01 должен проверить первый полный проход способности:

кнопка способности
→ выбор цели
→ AbilityPipeline
→ проверка защиты
→ проверка брони
→ нанесение урона
→ вывод результата в консоль

Главная цель:
Проверить, что данные из UnitData, UnitAbilityData и AbilityData могут пройти через Pipeline и изменить Runtime-состояние цели.


==================================================
2. ЧТО ВХОДИТ В ПРОТОТИП
==================================================

В прототип входит:

1. Минимальная тестовая сцена.
2. Три юнита в виде цветных квадратов.
3. Одна кнопка способности.
4. Подсветка доступных целей.
5. Выбор цели кликом.
6. AbilityPipeline для алгоритма deal_damage.
7. Проверка одноразовой защиты.
8. Проверка вероятностной брони.
9. Снятие HP.
10. Вывод результата в консоль.


==================================================
3. ЧТО НЕ ВХОДИТ В ПРОТОТИП
==================================================

В Prototype 01 не входит:

- поле боя;
- клетки;
- движение;
- поиск пути;
- препятствия;
- временные объекты;
- инициатива;
- раунды;
- очередь ходов;
- эффекты;
- кулдауны;
- заряды;
- смерть как полноценный процесс;
- DeathPipeline;
- анимации;
- спрайты;
- нормальный боевой UI;
- ИИ;
- сохранения;
- кампания.

Смерть пока не проверяется.

Если HP упало до 0 или ниже, это можно вывести в консоль, но отдельную систему смерти не создавать.


==================================================
4. ОБЪЕКТЫ НА ЭКРАНЕ
==================================================

На экране должно быть три цветных квадрата:

1. Archer
- Союзный юнит.
- Всегда активный.
- Имеет способность LongbowShot.

2. DefenseDummy
- Вражеский юнит.
- Имеет HP и физическую защиту.

3. ArmorDummy
- Вражеский юнит.
- Имеет HP и броню.

Под юнитами должна быть кнопка:

"Выстрел из лука"

При нажатии на кнопку активируется режим выбора цели.

После активации способности подсвечиваются только вражеские цели:

DefenseDummy
ArmorDummy

Клик по Archer не нужен.
Archer всегда считается активным юнитом.

==================================================
9. ПРАВИЛО ЗАЩИТЫ
==================================================

Защита — это одноразовая блокировка атаки по keyword.

Порядок:

1. Атака имеет keyword.
2. Цель имеет список active_defenses.
3. Если active_defenses содержит keyword атаки:
   - атака полностью блокируется;
   - соответствующая защита удаляется из active_defenses;
   - HP цели не меняется;
   - проверка брони не выполняется.
4. Если защиты нет:
   - атака переходит к проверке брони.

Пример:

attack keyword:
physical

target active_defenses:
physical

Результат:
- защита сработала;
- physical удален из active_defenses;
- урон не нанесен.


==================================================
10. ПРАВИЛО БРОНИ
==================================================

Броня — это вероятностный шанс полностью заблокировать входящий урон.

Каждая единица брони дает 20% шанс блока.

Диапазон брони:

0 armor = 0%
1 armor = 20%
2 armor = 40%
3 armor = 60%
4 armor = 80%
5 armor = 100%

Бронебойность уменьшает броню цели перед расчетом шанса.

Формула:

effective_armor = target.armor - armor_penetration

Ограничение:

effective_armor не может быть меньше 0.
effective_armor не может быть больше 5.

block_chance = effective_armor * 20

Пример:

target.armor = 3
armor_penetration = 1

effective_armor = 2
block_chance = 40%

Если броня сработала:
- входящий урон полностью блокируется;
- HP цели не меняется.

Если броня не сработала:
- HP цели уменьшается на damage.


==================================================
11. ПОРЯДОК ОБРАБОТКИ АТАКИ
==================================================

При клике по цели AbilityPipeline должен выполнить:

1. Получить source_unit.
2. Получить target_unit.
3. Получить UnitAbilityData.
4. Из UnitAbilityData получить AbilityData.
5. Проверить, что AbilityData.algorithm_id = deal_damage.
6. Получить parameters:
   - damage
   - armor_penetration
   - keyword
7. Проверить условия:
   - target_must_be_alive
   - target_must_be_enemy
8. Проверить защиту цели.
9. Если защита сработала:
   - удалить защиту;
   - вывести результат в консоль;
   - завершить Pipeline.
10. Если защита не сработала:
   - проверить броню.
11. Если броня сработала:
   - вывести результат в консоль;
   - завершить Pipeline.
12. Если броня не сработала:
   - снять HP.
13. Вывести текущее HP цели в консоль.


==================================================
12. МИНИМАЛЬНЫЙ RUNTIME ДЛЯ ПРОТОТИПА
==================================================

Полный Runtime-слой пока не нужен.

Но минимальный Runtime нужен обязательно, потому что HP, защита и команда меняются во время боя.

Минимальный UnitRuntime для Prototype 01:

data
- Ссылка на UnitData.

current_hp
- Текущее здоровье.

team_id
- Команда в текущем бою.
- Не хранится в UnitData.

active_defenses
- Текущие защиты юнита.
- В начале боя копируются из UnitData.defenses.
- Могут расходоваться.

active_immunities
- Текущие иммунитеты юнита.
- В Prototype 01 можно не использовать, но поле допустимо.

armor
- Текущая броня юнита.
- В начале боя копируется из UnitData.armor.

is_alive
- Жив ли юнит.
- В Prototype 01 смерть не обрабатывается полноценно.


==================================================
13. МИНИМАЛЬНАЯ СЦЕНА
==================================================

Предполагаемая сцена:

Prototype01Scene

На сцене:

- ArcherSquare
- DefenseDummySquare
- ArmorDummySquare
- AbilityButton

Визуально:

[Archer] [DefenseDummy] [ArmorDummy]

[Выстрел из лука]

Поведение:

1. При запуске сцены создаются три UnitRuntime.
2. ArcherRuntime назначается active_unit.
3. Кнопка "Выстрел из лука" выбирает LongbowShot как pending_ability.
4. Вражеские квадраты подсвечиваются.
5. Клик по DefenseDummy или ArmorDummy запускает AbilityPipeline.
6. После завершения Pipeline результат выводится в консоль.

14. ОЖИДАЕМЫЕ ЛОГИ В КОНСОЛИ
==================================================

Пример атаки по ArmorDummy:

Archer uses Выстрел из лука on ArmorDummy
Attack keyword: physical
No matching defense
Armor = 3
Armor penetration = 0
Effective armor = 3
Block chance = 60%
Armor roll: success / failure

Если success:
Armor blocked the attack
ArmorDummy current HP = 10

Если failure:
Damage dealt: 3
ArmorDummy current HP = 7


==================================================
15. КРИТЕРИИ ГОТОВНОСТИ ПРОТОТИПА
==================================================

Prototype 01 считается готовым, если:

1. На сцене есть три цветных квадрата.
2. Есть кнопка способности.
3. При нажатии кнопки подсвечиваются две вражеские цели.
4. По вражеской цели можно кликнуть.
5. Клик запускает AbilityPipeline.
6. Pipeline берет данные из UnitAbilityData и AbilityData.
7. Защита physical блокирует первый выстрел и расходуется.
8. Броня с вероятностью блокирует входящий урон.
9. Если защита и броня не заблокировали атаку, HP цели уменьшается.
10. Результат выводится в консоль.


==================================================
16. ГЛАВНЫЙ ПРИНЦИП ПРОТОТИПА
==================================================

Мы не строим всю игру.

Мы проверяем один вертикальный срез:

данные способности
→ выбор цели
→ Pipeline
→ защита
→ броня
→ HP

Все, что не нужно для этой проверки, откладывается.
